# ReperioNet benchmark results

Generated by `benchmarks/run-matrix.sh 100000 10` on 2026-06-07 12:54 UTC.

## Environment

- CPU: Intel(R) Core(TM) i7-6850K CPU @ 3.60GHz (8 cores, 3597.912 MHz)
- Memory: 31Gi total
- OS: Linux 6.8.0-101-generic
- .NET: 8.0.127
- Documents per run: 100000 email-like texts (en/de/fr 5:3:2, ~860 bytes average)

Device classes are simulated via CPU affinity (taskset); per-core clock speed and storage
speed cannot be throttled from user space, so phone-class numbers are optimistic — they
model reduced parallelism, not slower silicon.

Profiles: `full` = trigram + stemming + phonetic + stored content; `no-trigram` drops
substring recall; `compact` additionally stores no content copy (no snippets);
`smallest` additionally drops phonetic codes and removes stop words from the stem stream.

Multi-token queries default to all-terms (AND) semantics with an automatic any-term
fallback when fewer than Limit candidates match (`SearchQueryOptions.TermMatch`); the
latency battery shows both modes side by side. The gain grows with term selectivity —
this corpus's tiny synthetic vocabulary makes every term pathologically common, so the
all-terms numbers here are a lower bound.
